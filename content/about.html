How I check my work

  1. Run the stock thing first

    Before writing a replacement, run the existing rule on recorded data. The stock SigmaHQ setuid rule flagged 0 of the 2 attack events among 36 recorded events. That run is red on purpose: the stock rule missed the attack, and that is the finding. {{run:41838714456}} The latest passing run on main replays the same recording with the replacement rule. {{run:43100952362}}

  2. Test the tests

    Coverage says a line ran, not that a test would notice it breaking. I added six deliberate defects to kevgate, and all six passed its 227 tests until each got a test of its own. {{run:42960808156}}

  3. Compare against the original

    fuzzdiff runs the C parser and the Rust port on the same bytes; five seeded bugs were caught, and a 500,000-input control stayed clean. {{run:43035685955}}

  4. State the limits where the number is

    sinkline's page leads with its score on an outside benchmark. Right next to the number it says the fixes were picked from the earlier failures and that Bandit still leads over all 14 categories. {{run:43136290658}}
