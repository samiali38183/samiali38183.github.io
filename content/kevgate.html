A small vulnerability intake service. Scanner findings go in; a remediation queue comes out, ranked by CISA KEV membership, EPSS, CVSS and asset criticality. The repository also shows what shipping it carefully looks like: authentication, rate limits, container hardening, Kubernetes and Terraform, and a CI pipeline that tests the controls.

The problem

A raw scanner export sorts by CVSS, which puts a theoretical 9.8 ahead of a 7.5 that attackers are using today. KEV membership is the strongest prioritization signal that is freely available, so the service makes it the dominant factor and uses the rest to order everything else.

The second question is whether a small service like this can be shipped the way a production team would, with the security controls tested rather than described.

What it does

The score is 100 * (0.40*kev + 0.25*acr/8 + 0.20*epss + 0.20*cvss/10) / 1.05, from 0 to 100. The KEV weight equals the EPSS and CVSS weights combined, so a KEV finding never scores below a non-KEV finding on an asset with the same criticality; the one degenerate tie is broken in favor of KEV.

KEV is CISA's Known Exploited Vulnerabilities catalog: CVEs with evidence of exploitation in the wild. EPSS is a probability, from 0 to 1, that a CVE will be exploited in the next 30 days.

The API takes JSON findings or a Nessus/Tenable CSV export, upserts on (CVE, asset), and serves a ranked /queue, per-CVE views and stats. Scopes are findings:write, queue:read and admin. There are health, readiness and Prometheus endpoints, and a separate CLI command refreshes the KEV file from CISA so the API process never makes outbound calls.

Three implementation points

Key checks that do not leak timing

Keys are 256-bit random values and the server stores only their SHA-256. KeyStore.authenticate hashes the presented token and compares it against every stored digest with hmac.compare_digest, never exiting early, so response time does not reveal whether a key matched or how many bytes were right. A fast hash is deliberate: slow password hashes exist to protect low-entropy passwords, and running one on every request would hand an attacker a CPU lever.

Limiters in the right order

A token bucket per API key returns 429 with Retry-After. A second limiter counts failed authentications per source address and is checked before any key is looked at, so a brute-force attempt is throttled instead of getting free guesses. The failure limiter uses peek and charge so that checking does not itself spend a token. Both are in memory, which is a stated limitation: they are per replica and reset on restart.

Controls proven by tests, and a hash-locked build

The kind job does not just render the Helm chart. deploy/scripts/netpol-test.sh starts a labeled pod that must reach the service, an unlabeled pod in the same namespace that must time out, checks that the kevgate pod cannot open an outbound HTTPS connection, and submits a privileged pod that Pod Security restricted must reject. A second script then confirms the three audit events that the repository's Sigma rules target are in the API server audit log. Dependencies are pinned in requirements.lock with hashes; CI and the Docker build install it with --require-hashes, pip-audit scans that exact file, and a weekly workflow fails if a fresh compile would change it.

  • Nothing is deployed to a real AWS account. The Terraform (ECR, reports bucket, KMS key, workload and CI roles) was applied only to LocalStack, and the service does not call AWS. Releases go to GHCR.
  • One replica, SQLite on one volume, Recreate rollouts. That is a demonstration scope; DEPLOYMENT.md lists what production would change. The rate limiter is per process.
  • The scoring weights are a design choice, not evaluated against remediation outcomes.
  • The detection rules shipped with it have not been run against a real SIEM. They convert with sigma and are validated, no more.
  • Coarse access control. Three scopes, no per-asset authorization, and no key expiry or rotation workflow.
  • Bundled KEV file is a 5-entry sample. kevgate kev-refresh downloads the real catalog; the demo above used the sample.
