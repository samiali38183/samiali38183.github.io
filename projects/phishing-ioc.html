Phishing IOC Extractor

Python CLI that parses raw RFC 822 .eml phishing samples and extracts five categories of indicators of compromise — IPs, domains, URLs, email addresses, and MD5/SHA-1/SHA-256 hashes — into deduplicated, sorted JSON for downstream threat-intel workflows.

Python Automation Threat Intel
Zero external dependencies at runtime. Pure Python standard library — re, email, argparse, json, pathlib. pytest is dev-only.

What it does

  • Parses raw RFC 822 .eml files with the stdlib email module — handles multipart bodies and text extraction.
  • Runs five tuned regex extractors: IPv4, domains, URLs, email addresses, and MD5 / SHA-1 / SHA-256 hashes.
  • Deduplicates, sorts, and returns a single JSON object ready to feed a threat-intel enrichment pipeline.
  • Argparse CLI with pretty-print and file-output flags. Type hints and docstrings throughout.
  • 10-test pytest suite covering each extractor and edge cases — empty input, deduplication, case normalization. All passing.

Why it matters

Phishing triage in a real SOC is a volume problem. Analysts pull email samples out of a shared mailbox all day, and the first thing they need is a clean list of what to enrich — hashes to VirusTotal, domains to URLhaus, IPs to AbuseIPDB. Doing that by hand is error-prone; regexing it by hand every time is silly. This tool is the "give me the IOCs" step of that pipeline, isolated, tested, and portable.

Design decisions

  • Stdlib only. The extractor should install nowhere and run anywhere — no pip install required in a locked-down analyst environment.
  • Regex, not ML. IOC extraction is a solved problem for tuned patterns; the surface area is bounded and the false-positive story is manageable with careful boundaries.
  • JSON out. The output feeds other tools, not a human directly. Deduplicated and sorted so diffs are stable.
  • Tested. pytest suite is the contract — anyone forking can add a case and know they didn't break the others.
