Agent Engineering Lab

I design, orchestrate and ship software with teams of AI agents, then verify it like a security engineer: Hermes Agent, Claude Code, Codex, voice AI, cloud deployment and hardened production systems.

Agent Orchestration Voice AI AppSec
Overview on GitHub: github.com/samiali38183/agent-engineering-lab. A high-level look at how I work; implementation details stay private.

What I do

  • Multi-agent engineering: I run parallel AI sub-agents on separate workstreams, then integrate, review and gate their output with automated tests before anything ships.
  • Voice and conversational AI: production phone agents with tool use, live speech pipelines, and real-call evaluation across speech, voice and model vendors, including ElevenLabs.
  • Cloud and data: deployed on Fly.io with SQLite-backed storage, load-tested for concurrency, with measured results kept separate from estimates.
  • Integrations: scheduling and CRM connections behind clean provider interfaces, using OAuth and scoped keys, never customer passwords.
  • Benchmarking: reproducible test harnesses so decisions come from data, not opinions.

Security mindset

I treat an AI agent like any internet-facing system: authenticated inputs, isolated tenants, bounded cost, escaped output, minimal data retention, secrets kept out of prompts and code, and an audit trail. Along the way I found and fixed a real concurrency race before it could reach customers. It is the same discipline I bring to vulnerability management and detection engineering.

What it shows

  • I can scope, delegate and verify work across many agents at once, with 3,400+ automated tests as the safety net
  • I label every claim by evidence level, so nothing is oversold
  • I ship, measure and fix, across backend, voice, cloud and security
