Call Kettle — AI Voice Receptionist

A production AI voice-receptionist platform for small businesses — built on a Nous Hermes agent architecture with structured tool-use. Currently serving 10 active clients.

LLM Agents Production Voice / Telephony
Live service. Exact tech-stack details, pricing, and client identities are private — this page covers the architecture and the engineering decisions at a high level.

What it does

Call Kettle answers inbound customer calls for small businesses — pressure-washing, mobile detailing, home-service shops — the ones that lose revenue every time an owner misses a ring. The system picks up, talks like a real receptionist, books appointments against the client's calendar, qualifies leads, fires an SMS follow-up, and hands off to a human when the conversation needs one.

The agent architecture — why Hermes, why tool-use

The core of the system is an agent runtime built around Nous Hermes, chosen specifically for its strength at structured function-calling and its willingness to stay inside a schema instead of free-styling into hallucinations. Call Kettle's reliability depends on the model never inventing an appointment time that doesn't exist, a business policy the owner didn't give it, or a fact about the client it wasn't told.

The agent loop looks like this at a high level:

  1. Intent routing — classify the caller's turn into a bounded set of intents (book, reschedule, cancel, FAQ, qualify, escalate).
  2. Tool selection — Hermes picks a tool from a typed registry and emits a structured call. Every tool has a JSON schema; invalid calls are rejected before they ever touch the backend.
  3. Tool execution — the orchestrator runs the call (calendar lookup, availability, booking, SMS send, CRM lookup, etc.) and feeds the result back into the context.
  4. Confidence scoring — before each turn goes out as voice, the agent self-checks for ambiguity. Below threshold, it either asks a clarifying question or hands off.
  5. Graceful handoff — any unrecoverable state (payment disputes, angry caller, sensitive request) hands the call back to the business owner cleanly, with a transcript summary already drafted.

The result is an agent that stays in its lane. It books real appointments against real calendars. It doesn't make up prices. It doesn't pretend to be human. And it logs every tool call so the business owner can audit exactly what was said and done on their behalf.

What I built end-to-end

  • Agent runtime with intent routing, schema-validated function-calling, confidence scoring, and human handoff
  • Tool registry: calendar integration, SMS follow-up, lead-qualification form, CRM lookup, business-hours logic
  • Call session management with sub-second response latency and recovery across network drops
  • Per-client configuration layer so each business can define its own services, hours, FAQ, and escalation rules without touching code
  • Transcript + action logging for owner audit and model-improvement feedback loops

Why I built this

The project started as a technical bet: how reliable can a modern open-weights agent actually be when the stakes are real money and real customers? Small businesses turned out to be the ideal testbed — they feel every missed call directly in revenue, so the ROI math is obvious when it works. One owner, one line, one agent, measurable lift. From there it grew into a paying product.

Working on Call Kettle has taught me more about agent reliability, schema design, and where LLMs break under production load than any coursework ever would. Those lessons translate directly into the detection-engineering and security-automation work I want to do long-term — same discipline, different domain.
